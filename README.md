# Torchlight Helper 1.2.8-ocr.1

토치라이트: 인피니트의 타르타로스와 블러드 러스트 수술 준비를 돕는 Windows 10/11 x64용 비공식 추천 오버레이입니다. 화면과 게임 로그를 읽으며, 카드 선택과 확인은 사용자가 직접 진행합니다.

**[CPU OCR 실험판 ZIP 다운로드](https://github.com/highsun9941/torchlight-overlay/releases/tag/v1.2.8-ocr.1)** · [빌드·회귀 검사](https://github.com/highsun9941/torchlight-overlay/actions/workflows/verify.yml)

## 실행

1. 릴리스의 `TorchlightHelper-KO-1.2.8-ocr.1-win-x64.zip` 전체를 새 폴더에 풉니다. `Source code` ZIP은 실행 파일이 아닙니다.
2. 기존 오버레이를 종료하고 `TorchlightHelper.exe`를 실행합니다. .NET과 타르타로스 한국어 OCR 모델을 포함합니다.
3. 게임 언어를 맞추고 `콘텐츠 자동 감지`를 켭니다. 콘텐츠 자동 전환을 쓰려면 게임의 계정 관련 설정에서 로그를 활성화한 뒤 재접속합니다.
4. 로그를 자동으로 찾지 못하면 `로그 선택`에서 `UE_game/Torchlight/Saved/Logs/UE_game.log`를 지정합니다.
5. 블러드 러스트에서는 실제 인턴 의사 세라일 보유 단계를 설정합니다. 미보유는 그대로 `미보유`를 선택합니다.

게임은 창 모드 또는 테두리 없는 창 모드로 사용합니다. 설정 창과 툴팁이 선택지를 가리지 않게 합니다. 설정·기록은 실행 파일 옆 `user-data`에 저장됩니다.

## 자동 인식과 최대 성능

블러드 러스트 화면의 카드·수치 영역을 0.5초마다 가볍게 비교합니다. 장면이 바뀌면 이전 추천을 숨기고, 화면이 안정되면 자동으로 다시 읽습니다. 수조는 배경 픽셀 변화 대신 총합과 활성 × 수량이 검증된 판독값을 비교합니다. 빈 수조의 불꽃과 확인되지 않은 글자 소실만으로 추천을 폐기하지 않습니다. 게임 로그 이벤트가 끊겨도 동작하며, OCR 실행 중 다른 화면으로 넘어가면 그 결과를 버립니다. 로그 연결은 콘텐츠 자동 전환과 화면 이벤트 감지를 보완합니다.

블러드 러스트 탭의 **CPU 사용 → 최대 성능**은 OS가 보고하는 모든 논리 CPU 스레드를 사용하고, 잘 읽히지 않는 카드 제목에 확대·대비 처리를 추가로 시도합니다. 코어 수는 자동으로 결정합니다. 기본 균형 모드는 기존 절반 코어·최대 8개 제한을 유지합니다.

이 실험 브랜치의 한국어 카드 인식은 포함된 PaddleOCR 모바일 ONNX 모델을 CPU로 실행합니다. 모델을 한 번 로드하며 기본 1스레드로 잘라낸 글자 영역만 읽습니다. Python·GPU 설치나 외부 OCR 서버는 필요하지 않습니다. 엔진 종류와 모델 오류는 로그에 기록됩니다.

수치는 예상 위치 주변에서 다시 찾고, **활성 × 수량이 화면의 총합과 일치하는 경우**만 채택합니다. 세라일 미보유로 새로고침 기능이 없는 도구 선택은 0회로 처리합니다. 첫 라운드부터 추천 대상입니다.

화면 크기와 패치, 애니메이션 상태에 따라 실패할 수 있습니다. 읽지 못한 값은 임의로 확정하지 않으며, `인식 확인 필요`에 확인할 항목을 표시하고 추천을 숨깁니다. 제공된 실제 한국어 창 네 장은 `vorax/fixtures/korean`의 회귀 검사에 포함합니다.

## 확대 스캔

각 프레임에서 카드별 글자줄을 찾아 제목을 읽습니다. 전체 스캔에서 카드 이름을 읽지 못하면 해당 카드에 파란 테두리를 표시합니다. 직접 마우스를 올려 게임 좌측 하단의 확대 카드를 보여 주세요. 끊어진 파란 테두리는 양쪽 경계와 위아래 선을 맞춰 찾습니다. 제목과 그림을 대조하고, 깨진 제목은 정확한 앞뒤 글자와 유일한 이름 후보로만 보완해 같은 카드 이름을 두 번 확인한 뒤 그 위치의 판독만 보완합니다. 커서 위치를 잡지 못해도 미확인 후보 중 하나에만 대응하는 확대 카드는 읽을 수 있습니다. 같은 그림 후보가 겹칠 때만 커서 위치로 구분합니다. 다른 카드도 실패했다면 차례로 올립니다. 확대 인식 완료 후에는 마우스를 카드 밖으로 옮기면 추천을 갱신합니다. 장면·라운드·선택지가 바뀌면 확인 결과를 초기화합니다. 마우스나 게임 입력을 자동으로 조작하지 않습니다.

같은 게임 창의 캡처 세션을 재사용합니다. Windows가 요구하는 캡처 표시 테두리는 남을 수 있지만, 매 0.5초마다 세션을 새로 여는 방식은 사용하지 않습니다.

## 단축키

| 콘텐츠 | 키 | 기능 |
|---|---|---|
| 타르타로스 | Ctrl+Shift+S | 지금 인식 |
| 타르타로스 | Ctrl+Shift+R | 자동 인식 전환 |
| 타르타로스 | Ctrl+Shift+H | 오버레이 전환 |
| 블러드 러스트 | Ctrl+Alt+X | 지금 인식 |
| 블러드 러스트 | Ctrl+Alt+V | 오버레이 전환 |

추천의 달성률은 현재 인식 상태와 기존 확률표로 계산한 추정입니다. 11~13라운드 수술 플랜은 캐릭터 조건에 따라 직접 판단하도록 안내합니다.

## 로컬 진단

실패 항목과 판독 결과는 `user-data/vorax/overlay.log`에 남습니다. 각 시도에는 스캔 번호, 프로세스 번호, 단계, 원본 캡처 크기, OCR 입력 크기·원문, 변경된 UI 영역의 유사도·검증된 수조 값의 전후 차이, 확대 경계 후보 수·점수, 확대 판독과 보류 이유를 기록합니다. 10초마다 캡처 상태를 기록하며 로그는 현재 파일과 이전 파일로 제한합니다.

실패 또는 결과 폐기 시 `user-data/vorax/diagnostics`에 원본 크기의 게임 캡처, 비교 화면, OCR 입력 이미지와 JSON을 최대 세 묶음으로 순환 저장합니다. 저장 간격은 최소 15초이며 자동 전송하지 않습니다. 인식 오류를 확인할 때 로그와 이 폴더를 함께 참고할 수 있습니다. 저장된 게임 PNG를 같은 실행 경로로 검사할 수도 있습니다. 창 제목줄은 자동으로 제외합니다.

```powershell
$env:VORAX_LANGUAGE = 'ko'
$env:VORAX_OCR_MODE = 'accurate'
.\vorax-overlay.exe --inspect .\screen.png .\diagnosis
```

`diagnosis/reading.json`과 `client.png`가 생성됩니다. 진단은 로컬에 저장하며 자동 전송하지 않습니다.

## 소스 빌드

Windows에서 Rust stable, Visual Studio C++ Build Tools, .NET 9 SDK, Python 3를 준비합니다.

```powershell
cargo test --release --locked --workspace --manifest-path vorax/Cargo.toml
dotnet test tartarus/tests/Tartarus.Rules.Tests/Tartarus.Rules.Tests.csproj -c Release -p:Platform=x64
.\build.ps1
python package.py
```

첫 빌드는 NuGet·Cargo 패키지와 SHA-256으로 검증하는 OCR 모델을 다운로드합니다. 모델은 빌드 결과에 포함됩니다. GitHub Actions는 Rust 추적 회귀, 실제 화면 검사, Windows 빌드, UI 실행과 ZIP 무결성을 검사한 뒤 실행용 파일을 제공합니다.
